# My_Language — подробная документация

## 1. Назначение проекта

`My_Language` — учебный компилятор небольшого императивного языка с футбольной тематикой в ключевых словах. Это не интерпретатор: исходная программа проходит несколько стадий, после которых компилятор записывает ассемблер для стекового учебного процессора `Processor`.

```text
исходный текст
    → таблица имён и лексический анализ
    → синтаксический разбор и AST
    → проверка областей видимости и связывание переменных
    → свёртка констант и упрощение дерева
    → Graphviz DOT + ассемблер Processor
    → (необязательно) ассемблер Processor и запуск эмулятора
```

Компилятор написан на C++11. Язык ориентирован на целочисленные учебные программы: арифметику, переменные, условия, циклы, функции и рекурсию.

## 2. Требования и сборка

Для компиляции только языка нужны компилятор C++11 и CMake 3.21 или новее. Для объединённого запуска через `run_program` рядом с каталогом `My_Language` должен находиться репозиторий процессора в каталоге `Processor-reference`:

```text
parent/
├── My_Language/
└── Processor-reference/
```

Если репозиторий процессора ещё не скачан:

```sh
git clone https://github.com/Arseny-Dernovich/Processor.git Processor-reference
```

Сборка компилятора и компиляция исходника в ассемблер:

```sh
cmake -S . -B build
cmake --build build
./build/read recursion_example.txt
```

После запуска компилятора в его текущем рабочем каталоге создаются `output.asm` и `tree.dot`. При приведённой выше команде компилятор запущен из корня репозитория, поэтому файлы появятся в корне. При работе через цель `run_program` рабочий каталог — `build/`.

Полная цепочка: My_Language → ассемблер Processor → эмулятор:

```sh
cmake -S . -B build
cmake --build build --target run_program
```

По умолчанию цель компилирует `recursion_example.txt`; ожидаемый результат вычисления факториала — `120`. Другой файл задаётся при конфигурации:

```sh
cmake -S . -B build -DLANGUAGE_PROGRAM="$PWD/complex_test.txt"
cmake --build build --target run_program
```

Для `complex_test.txt` ожидаемый вывод эмулятора — `21`, `1024`, `55` (по одному числу на строку): Fibonacci(8), 2^10 и сумма от 1 до 10.

Чтобы вернуть стандартный файл, укажи его явно:

```sh
cmake -S . -B build -DLANGUAGE_PROGRAM="$PWD/recursion_example.txt"
```

### Старый Makefile

Makefile по-прежнему собирает только компилятор языка:

```sh
make
./read.exe recursion_example.txt
```

Если аргумент не указан, программа читает `my_programm.txt`. Проверки регрессии запускаются отдельно после сборки:

```sh
python3 tests/run_tests.py
```

Скрипт проверяет сгенерированные инструкции небольшим встроенным интерпретатором, так что для него не требуется отдельная сборка процессора.

### Изображение AST

Для PNG нужен установленный Graphviz (`dot`). В Ubuntu/Debian:

```sh
sudo apt install graphviz
```

Цель CMake компилирует `example.txt`, создаёт `tree.dot` и преобразует его в `build/tree.png`:

```sh
cmake --build build --target example
```

Либо вручную после генерации `tree.dot`:

```sh
dot -Tpng tree.dot -o tree.png
```

## 3. Быстрый пример

Функция задаётся необычно: сначала идёт её тело между `/:first_half` и `/:second_half`, и только затем заголовок с именем и параметрами. Вот рекурсивный факториал и точка входа:

```text
/:first_half
    start_game
        SSUUII 1 whistle
    end_game pass stadium_open n pressing 1 stadium_close

    SSUUII n assist transfer $factorial$ stadium_open offside n foul 1 stadium_close whistle
/:second_half GOAT $factorial$ stadium_open GOAT n stadium_close

/:first_half
    VAR transfer $factorial$ stadium_open offside 5 stadium_close whistle
/:second_half GOAT $main$ stadium_open stadium_close
```

Первая функция возвращает 1, когда `n <= 1`; иначе возвращает `n * factorial(n - 1)`. Вторая функция без параметров вызывает факториал и печатает результат.

## 4. Синтаксис языка

Пробелы и переводы строк разделяют лексемы. Пунктуационные символы в обычном смысле почти не используются: вместо них применяются специальные слова. В конце обычной инструкции обязателен `whistle`. Для блока `if` или `while` отдельный `whistle` не пишется: парсер добавляет его в AST сам.

### 4.1 Таблица ключевых слов и операторов

| Токен языка | Значение | Пример |
|---|---|---|
| `GOAT` | объявить целочисленную переменную или параметр | `GOAT total score 0 whistle` |
| `score` | присваивание | `total score total goal 1 whistle` |
| `goal`, `foul` | сложение, вычитание | `a goal b`, `a foul b` |
| `assist`, `substitute` | умножение, целочисленное деление | `a assist b`, `a substitute b` |
| `leader`, `underdog` | `>`, `<` | `pass stadium_open a leader b` |
| `advantage`, `pressing` | `>=`, `<=` | `pass stadium_open a pressing b` |
| `draw`, `gap` | `==`, `!=` | `pass stadium_open a draw b` |
| `stadium_open`, `stadium_close` | круглые скобки | `stadium_open a goal b stadium_close` |
| `start_game`, `end_game` | начало и конец блока | `start_game ... end_game` |
| `pass` | условный блок `if` | `end_game pass condition` |
| `dribble` | цикл `while` | `end_game dribble condition` |
| `VAR` | вывести значение выражения | `VAR total whistle` |
| `SSUUII` | вернуть значение из функции | `SSUUII total whistle` |
| `transfer` | вызвать функцию | `transfer $sum$ stadium_open ...` |
| `offside` | начать очередной аргумент вызова | `offside x offside 4` |
| `whistle` | завершить обычную инструкцию | `x score 2 whistle` |
| `/:first_half`, `/:second_half` | обрамить тело функции | `/:first_half ... /:second_half` |

`shoot` (псевдоним `else`) распознаётся лексером, но синтаксический анализатор и backend пока не реализуют ветку `else`. `FUNC` и `NEW_BLOCK` также есть в таблице слов, но не являются конструкциями пользовательского синтаксиса, поддержанными компилятором.

### 4.2 Имена

- Имена переменных состоят из букв, цифр и `_`, например `total`, `value2`, `loop_index`.
- Имя функции обрамляется знаками `$`: `$main$`, `$factorial$`, `$sum_until$`.
- Имена переменных и функций хранятся в разных категориях таблицы имён.
- Имена ключевых слов чувствительны к регистру: используйте написание из таблицы.
- Лексер ограничен фиксированными таблицами и буферами; не следует считать длинные имена или огромные исходники поддерживаемыми.

### 4.3 Формальная грамматика

Ниже приведена компактная EBNF для реально поддерживаемых форм. `*` — ноль или более повторений, `+` — одно или более, `?` — необязательная часть. Разделитель аргументов — именно слово `offside`, не запятая.

```ebnf
program          = { global_declaration | function } ;

global_declaration
                  = declaration, "whistle" ;

function         = function_body, "GOAT", function_name,
                    "stadium_open", { parameter }, "stadium_close" ;
function_body    = "/:first_half", statement, { statement },
                    "/:second_half" ;
parameter        = "GOAT", identifier ;

statement        = declaration, "whistle"
                  | assignment, "whistle"
                  | print_statement, "whistle"
                  | return_statement, "whistle"
                  | call, "whistle"
                  | control_statement ;

declaration      = "GOAT", identifier, [ "score", expression ] ;
assignment       = identifier, "score", expression ;
print_statement  = "VAR", expression ;
return_statement = "SSUUII", expression ;

control_statement
                  = block, ( "pass" | "dribble" ), condition ;
block            = "start_game", statement, { statement }, "end_game" ;
condition        = "stadium_open", expression, comparison,
                    expression, "stadium_close" ;
comparison       = "leader" | "underdog" | "advantage"
                  | "pressing" | "draw" | "gap" ;

expression       = term, { ( "goal" | "foul" ), term } ;
term             = primary, { ( "assist" | "substitute" ), primary } ;
primary          = integer | identifier
                  | "stadium_open", expression, "stadium_close"
                  | call ;

call             = "transfer", function_name, "stadium_open",
                    { "offside", expression }, "stadium_close" ;
```

Парсер ожидает непустые тела функций и блоков. Условная форма — это блок, затем `pass`/`dribble`, затем круглое условие, например:

```text
start_game
    VAR n whistle
end_game pass stadium_open n pressing 1 stadium_close
```

### 4.4 Приоритет и вычисление выражений

Приоритет от высокого к низкому:

1. Скобки и атомы (`число`, `переменная`, вызов).
2. `assist` и `substitute` (`*`, `/`).
3. `goal` и `foul` (`+`, `-`).
4. Сравнение — только в заголовке `pass` или `dribble`.

Операторы каждого арифметического уровня разбираются слева направо. Деление целочисленное. Поддерживаются только целые десятичные литералы; отрицательного литерала и унарного минуса нет. Например, `0 foul 1` создаёт отрицательное значение арифметическим выражением.

## 5. Переменные и области видимости

Объявление создаёт имя только в текущей области:

```text
GOAT counter score 0 whistle
counter score counter goal 1 whistle
```

- Глобальное объявление размещается на верхнем уровне программы и доступно всем функциям.
- Каждое тело функции имеет собственную область. Параметры объявляются в ней до локальных переменных.
- Каждый блок `pass` или `dribble` создаёт дочернюю область видимости.
- Поиск имени идёт из внутренней области наружу: локальное объявление может скрыть одноимённое внешнее.
- После выхода из блока имя, объявленное только внутри блока, недоступно.
- Повторное объявление одного имени в одной области — ошибка. Повторное имя во вложенной области разрешено.
- Использование необъявленной переменной, неизвестной функции или неверного числа аргументов останавливает компиляцию с диагностикой.

Процессор имеет адресуемую RAM; компилятор назначает переменным ячейки. Лимиты реализации включают таблицу имён/функций фиксированного размера и не более 10 000 выделенных ячеек RAM.

## 6. Функции, вызовы и рекурсия

### Объявление

Тело функции предшествует заголовку. Формат заголовка:

```text
/:first_half
    ...инструкции тела...
/:second_half GOAT $function_name$ stadium_open GOAT first GOAT second stadium_close
```

Каждый параметр записывается как отдельная пара `GOAT имя`. Параметры — локальные переменные функции. Функции собираются в таблицу до связывания тел, поэтому рекурсивные и взаимно рекурсивные вызовы могут ссылаться на функции, описанные позже.

### Вызов

```text
transfer $subtract$ stadium_open offside 9 offside 4 stadium_close
```

Аргументы идут после отдельных `offside` и вычисляются слева направо. Число аргументов проверяется во время компиляции. Значение функции можно использовать в выражении, передать как аргумент, вернуть или вывести.

Вызов как отдельная инструкция тоже допустим:

```text
transfer $do_work$ stadium_open stadium_close whistle
```

Результат такого вызова игнорируется.

### Возврат и точка входа

`SSUUII expression whistle` возвращает вычисленное целое значение и завершает текущий вызов. Если выполнение доходит до конца функции без `SSUUII`, backend генерирует неявный возврат `0`.

Backend вызывает `$main$` без параметров, если такая функция есть. Если функции `$main$` нет, используется первая объявленная функция; у неё также не должно быть параметров. Функция с параметрами не может быть точкой входа.

### Кадры вызовов и рекурсия

Для параметров и локальных переменных каждой функции при связывании выделяется непрерывный диапазон ячеек RAM — `frame_start` и `frame_size`. Эти адреса статичны для функции, то есть все рекурсивные уровни используют одни и те же адреса. Поэтому backend сохраняет содержимое диапазона вызывающей функции на стеке перед вызовом и восстанавливает после возврата:

```text
сохранить ячейки текущего кадра
вычислить и положить аргументы на стек
call func_name
восстановить ячейки текущего кадра
положить результат из ax на стек выражений
```

В начале функции параметры снимаются со стека в назначенные ячейки в обратном порядке, что сохраняет исходное соответствие аргументов параметрам. Возвращаемое значение помещается в `ax`. Локальные значения внешнего вызова переживают вложенный/рекурсивный вызов; глобальные переменные в кадр не входят и остаются общими.

Это кадр вызова, реализованный программно поверх стекового процессора, а не нативный ABI с отдельным frame pointer. Размер стека и допустимая глубина рекурсии ограничиваются самим эмулятором и доступной памятью.

## 7. Этапы компиляции и устройство кода

### Лексический анализ — `Read.cpp`, `Read.h`

`Build_Name_Table` предварительно собирает имена идентификаторов и функций. Затем `Lexical_Analyzer` преобразует исходный текст в массив токенов: числа, идентификаторы, ключевые слова, операторы и функции. Слова и их соответствия описаны в `Read.h`.

### Синтаксический анализ — `Syntax_Analis.cpp`

Рекурсивный спуск строит AST (абстрактное синтаксическое дерево). `Parse_Primary`, `Parse_Term` и `Parse_Expression` реализуют уровни арифметического приоритета; отдельные функции разбирают объявления, присваивания, блоки, условия, вызовы и функции.

AST использует связи `left` и `right`. Списки инструкций и списки функций представляются цепочками через `right`, а выражение — бинарными узлами.

### Проверка и связывание — `Build_Table_Name_Func.cpp`

Сначала собирается список функций и количество параметров, затем связываются глобальные инструкции и тела функций. Создаются `Scope`, проверяются повторные объявления и неизвестные имена, каждому объявлению назначается `slot`. Ссылки на переменные получают тот же слот. Для вызова сверяется число аргументов.

### Упрощение — `Simply.cpp`

`Fold_Constants` вычисляет поддеревья с числовыми константами. `Remove_Neutral_Elements` удаляет некоторые нейтральные элементы (`x + 0`, `0 + x`, `x * 1`, `1 * x`). Упрощение выполняется после связывания имён.

### Генерация DOT — `DOT.cpp`

`Export_Tree_To_Dot` записывает дерево в `tree.dot`. DOT можно визуализировать Graphviz. Экспорт дерева вызывается основной программой при каждой успешной компиляции.

### Генерация ассемблера — `Back_end.cpp`

Backend генерирует стековые инструкции для выражений, ветвлений, циклов, вызовов и возвратов. В ассемблер включаются комментарии-подсказки, например имя переменной/слота, начало условий и блоков, сохранение кадра и вход в функцию. Эти комментарии не являются инструкциями процессора.

### Точка входа процесса — `Main.cpp`

`Main` выбирает входной файл (аргумент командной строки либо `my_programm.txt`), загружает текст и вызывает этапы компиляции в установленном порядке. `CMakeLists.txt` содержит отдельные цели компилятора, assembler/emulator процессора, `example` и `run_program`.

## 8. Выходные файлы

| Файл | Назначение |
|---|---|
| `output.asm` | ассемблер, сгенерированный языковым компилятором; содержит поясняющие комментарии |
| `tree.dot` | AST в формате Graphviz DOT |
| `tree.png` | визуализация DOT, создаваемая CMake-целью `example` |
| `processor_input.asm` | копия `output.asm`, переданная ассемблеру Processor в общей цепочке |
| `output.txt` | текстовое представление машинной программы, создаваемое Processor |
| `output.bin` | бинарный результат assembler Processor |

Пути `output.asm` и `tree.dot` относительны текущему рабочему каталогу процесса `read`, а не пути исходного файла. При запуске CMake-цели файлы лежат в каталоге сборки.

make

В тестах проверяется не только успешная генерация ассемблера, но и наблюдаемый результат выполнения инструкций. Отрицательные тесты проверяют, например, недоступность имени после блока и несовпадение количества аргументов.

## 10. Диагностика и типичные ошибки

- `Unknown variable` — имя не объявлено в текущей или внешней области; переменная из уже завершившегося блока использоваться не может.
- `Unknown function` — отсутствует объявление функции с таким именем или вызов записан не как `$name$`.
- `needs N arguments, got M` — число `offside`-аргументов вызова не совпадает с числом параметров.
- `missing 'whistle'` — после обычной инструкции пропущен обязательный завершающий токен.
- `Ожидалось 'stadium_close'` — незакрытая пара скобок либо выражение/условие построено неверно.
- Assert/ошибка разбора — часто означает неверный порядок элементов функции, блока или выражения; сверяйтесь с формами из грамматики.
- `Graphviz not found` — компилятор языка можно собрать отдельно, но для PNG нужно установить Graphviz и повторно выполнить цель `example`.
- Ошибки сборки Processor относятся к соседнему репозиторию и его требуемым заголовкам/исходникам; сборка одного `read` не требует Processor.

Парсер сейчас использует утверждения и сообщения, которые не всегда указывают точную строку и столбец. Для диагностики сначала проверьте закрывающие слова, обязательные `whistle` и правильную структуру `/:first_half` → тело → `/:second_half` → заголовок.

## 11. Текущие ограничения

- Поддерживается целочисленная арифметика; других типов, массивов и пользовательских структур нет.
- `else` (`shoot`) пока не реализован, хотя слово присутствует в лексической таблице.
- Нет логических операций и объединения нескольких сравнений; условие — одно сравнение двух арифметических выражений.
- Нет унарного минуса и отрицательных литералов.
- Тело функции и управляющего блока должно содержать хотя бы одну инструкцию.
- Обработка синтаксических ошибок пока не везде безопасна и информативна; некоторые неверные входы завершаются `assert`.
- Используются массивы и лимиты фиксированного размера; компилятор учебный и не рассчитан на большие исходные тексты.
- Освобождение AST и полное владение узлами ещё не доведено до промышленной модели.
- Компилятор выдаёт ассемблер конкретного учебного Processor, а не машинный код для обычной архитектуры.

## 12. Краткий справочник форм

```text
; Глобальная переменная
GOAT global_value score 10 whistle

; Объявление локальной переменной и присваивание
GOAT local_value score 0 whistle
local_value score local_value goal 1 whistle

; Вывод
VAR local_value whistle

; Ветвление — блок пишется до pass и условия
start_game
    VAR 1 whistle
end_game pass stadium_open local_value pressing 5 stadium_close

; Цикл
start_game
    local_value score local_value goal 1 whistle
end_game dribble stadium_open local_value underdog 5 stadium_close

; Функция с двумя параметрами и возвратом
/:first_half
    SSUUII left goal right whistle
/:second_half GOAT $sum$ stadium_open GOAT left GOAT right stadium_close

; Вызов sum(2, 3)
VAR transfer $sum$ stadium_open offside 2 offside 3 stadium_close whistle
```
